Fichier 1 — dashboard_arbitre.html

Dashboard Déclaration — chargement du son

/* ── Klaxon ─────────────────────────────────────────────── */
const klaxon = new Audio(CFG.klaxonUrl);
klaxon.preload = 'auto';

function playKlaxon() {
    try {
        klaxon.currentTime = 0;
        klaxon.play();
    } catch (e) {}
}
new Audio(CFG.klaxonUrl) — crée un objet audio en mémoire pointant vers klaxon.mp3 (chemin injecté par Django via la balise {% static %}).

preload = 'auto' — demande au navigateur de télécharger le fichier MP3 immédiatement au chargement de la page, et non au moment où on en a besoin. Évite un délai audible lors du premier déclenchement.

currentTime = 0 — remet la tête de lecture à zéro avant chaque lecture. Sans ça, si le son joue encore (ex : deux événements simultanés), play() pourrait être ignoré ou le son ne repartirait pas du début.

try / catch (e) {} — les navigateurs modernes bloquent audio.play() si l'utilisateur n'a pas encore interagi avec la page (politique anti-autoplay). Le catch vide empêche une exception non gérée de planter le reste du script.

Condition 1 Fin du chrono de période (8 min = 0)

// Dans dashRaf() — boucle requestAnimationFrame (60×/s)
const t  = timeLeft();   // secondes restantes (décimales)
const tC = Math.ceil(t); // arrondi supérieur → valeur affichée

if (C.running && t <= 0 && !C.alertedEnd) {
    C.alertedEnd = true;  // verrou : ne sonne qu'une seule fois
    C.running    = false; // arrête le chrono côté client
    C.frozenTime = 0;
    C.startedAt  = null;
    playKlaxon();          // ← KLAXON SONNE
}
C.running — booléen, vrai si le chrono de période est en cours. Empêche le déclenchement si le chrono est déjà arrêté manuellement.

t <= 0 — le temps calculé localement (interpolation client) est épuisé. timeLeft() retourne une valeur décimale en secondes basée sur C.frozenTime et C.startedAt.

!C.alertedEnd — sans ce flag, la boucle RAF tournerait 60 fois par seconde et appellerait playKlaxon() 60 fois en une seconde. Ce flag garantit un seul déclenchement par fin de période. Il est remis à false au prochain démarrage du chrono (applyServerChrono).
⚠️ Le chrono s'arrête côté client immédiatement (C.running = false). Le serveur est informé séparément. Si la connexion est lente, l'affichage reste figé à 00:00 jusqu'à la prochaine action.

Condition 2 Shot clock expiré (30 s = 0)

// Dans dashRaf() — juste après la condition du chrono
const raw = shotLeft();     // secondes restantes shot clock (décimales)
const v   = Math.ceil(raw); // arrondi supérieur → valeur affichée

if (SC.running && raw <= 0 && !SC.alertedEnd && !shotAutoResetting) {
    SC.alertedEnd     = true;  // verrou anti-doublon (RAF)
    playKlaxon();              // ← KLAXON SONNE

    shotAutoResetting = true;  // empêche un 2e appel serveur simultané
    api({ action: 'shot_expired' }).then(r => {
        if (r.chrono) applyServerChrono(r.chrono);
        if (r.shot)   applyServerShot(r.shot);
        SC.alertedEnd     = false; // libère le verrou une fois serveur répondu
        shotAutoResetting = false;
    }).catch(() => { shotAutoResetting = false; });
}
SC.running — vrai uniquement si le shot clock tourne. Si le joueur a déjà tiré ou si le clock est en pause, cette condition est fausse → pas de klaxon intempestif.

!SC.alertedEnd — même principe que C.alertedEnd : empêche la boucle RAF d'appeler playKlaxon() 60×/s quand le temps est à 0.

!shotAutoResetting — deuxième verrou distinct. SC.alertedEnd est remis à false dès que le serveur répond (applyServerShot). S'il y a un léger délai réseau et que le RAF tourne encore avec raw <= 0, sans shotAutoResetting une deuxième requête shot_expired serait envoyée au serveur.

api({ action: 'shot_expired' }) — notifie le serveur Django pour qu'il réinitialise le shot clock côté base de données. La réponse resynchronise le client (applyServerShot).

Fichier 2 — score_board.html

Scoreboard Déclaration — objet audio + flag

const sbKlaxon      = new Audio(MD.klaxon || '');
// MD.klaxon = URL du MP3 injectée par Django
// || ''     = si la clé est absente, crée un Audio vide sans crash

let ovKlaxonFired = false;
// flag : a-t-on déjà sonné pour le temps mort / pause en cours ?
sbKlaxon — objet audio séparé de celui du dashboard. Le scoreboard est une page distincte (second écran) donc chaque page gère son propre son indépendamment.

|| '' — si MD.klaxon est null ou undefined, new Audio('') crée un objet audio vide. Appeler play() dessus lancera une exception attrapée par le try/catch sans planter la page.

ovKlaxonFired — flag global réinitialisé à false au début de chaque nouveau temps mort (dans handleOverlay()).

Condition 3 Fin du temps mort ou pause inter-période

// Dans rafOv() — boucle RAF du compte à rebours de l'overlay
function rafOv() {
    const rem = Math.max(0, ovEndTs - Date.now() / 1000); // sec restantes

    // ... mise à jour affichage des chiffres (1:00 → 0:00) ...

    if (rem > 0) {
        ovRafId = requestAnimationFrame(rafOv); // continue le countdown
    } else {
        // rem == 0 → temps mort / pause terminé(e)

        if (!ovKlaxonFired) {      // verrou : sonner UNE seule fois
            ovKlaxonFired = true;
            try {
                sbKlaxon.currentTime = 0;
                sbKlaxon.play();    // ← KLAXON SONNE
            } catch(e) {}
        }

        el.classList.remove('active');           // cache l'overlay TM/Pause
        if (fluidCanvas) fluidCanvas.classList.remove('active'); // éteint le fond WebGL
        ovRafId = null;                          // arrête la boucle RAF
    }
}
ovEndTs — timestamp Unix (en secondes) de la fin du temps mort, envoyé par le serveur dans la réponse API. La soustraction ovEndTs - Date.now()/1000 donne le temps restant en temps réel, sans dérive.

rafOv() récursive — tant que rem > 0, la fonction se réappelle via requestAnimationFrame (~60×/s). Quand rem = 0, elle ne se réappelle plus → la boucle s'arrête naturellement.

!ovKlaxonFired — même logique que les autres verrous : au moment précis où rem passe à 0, RAF peut encore appeler rafOv une ou deux fois. Ce flag empêche plusieurs sons simultanés.

Réinitialisation de ovKlaxonFired — dans handleOverlay(), dès qu'un nouveau temps mort commence : ovKlaxonFired = false. Sans ça, le flag resterait true et les temps morts suivants ne sonneraient jamais.
